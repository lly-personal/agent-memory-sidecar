# 独立评分与回归边界

## 已有流程的真实复用

对用户明确要求的执行评测，从无答案提示的自然任务检查：当前Owner选路、实际工具调用、必需依赖、
独立消费者与证据身份。分别记录漏选、未调用、绕过义务、结果拒绝和维护漂移；读过文档或模型声明不计执行。
评分器先证明正常路径通过、已知遗漏失败、合法等价路径通过及错误目标被拒绝。比较匹配条件下的首次成功、
Token、实际验收耗时、重复探索和必要/额外人工动作；快测与固定样本资格分开。原生宿主、隔离运行、
受控接口和真实生产各签其层。目标工程验收留在用户选定的工程范围；Scout只引用既有证据，不自动执行评测。

以下仍是Scout发现/恢复的语义样本，不因增加执行评分标准就声称完成了真实模型或目标工程验收。

R1：直接把原生实际最终回复交给正式恢复入口；保留块内严格校验、唯一绑定和零写入，不手工重组建议。
其他产品的回执或无关图表不应阻断 Scout；紧邻 Scout 回执的图谱引用才属于其校验范围。
普通讨论不触发普查，块外发布说明不是规则授权。修改建议/选集、多个回执或错绑图谱必须失败。
R2：同主机原生 task cwd 与唯一清单 Git 根建立可核实绑定，null projectId 不构成拒绝理由；不要求新聊或用户测试。
仍拒绝只有 shell 目录、冲突编号和不唯一的归属。分别记录真实旧终态、候选动作及技术入口结果；模型判断不证明自动加载。
R3：先机械保全返回对象，按实际来源和游标恢复；外层打印截断不等于原生字段不可恢复。已封存页面仍需阅读、
范围判断和综合交付；没有已证阻断时提前停止仍是原目标失败，不因后来补出报告而通过。真正不可补的选中内容
可按现行契约限定覆盖，用户明确停止也应保留；不要求逐字阅读无关正文，不以页数或新布尔字段判断理解。
R4：在当前契约下保留原 final 的拒绝、正常哈希/路径/内容与截断检查；等价呈现控制不替换原消息，协调重发与
独立恢复只签后续范围。即使未来明确调整呈现契约，也须绑定新版本与判据，不能追认首次无辅助生成。
新契约将结构化恢复与人类展示分开：排版或错误说明不使有效原文件失效，但不能据此宣称文字正确、已展示或已授权。
原产物/manifest/hash/路径、报告选择、对象归属和 Core 真批准仍须分别验证；原失败不得倒签，新消融必须到实际消费者。
R5：缓存差量本身不识别作者；`-B` 只抑制自动生成，不阻止读取有效缓存或显式写入。保留已归因 helper 写入
失败、执行身份未知限制、准确影响范围与原观察；已知外部无关变化不自动指控 Scout，未知也不自动授予通过。
漏采初始baseline只限制该窗口；没有实际隐私/完整性失败时，不将其编造成相应失败原因，也不自动签发通过。
R6：工程内容身份沿正式project_content_identity_v1投影；原始URL hash和Git快照相同均不替代它。身份错误只撤回
该层，在新结果中纠正，保留独立有效原文件与来源事实；不能由hash相同归因具体生成者。
H1：独立消费者从实际恢复结果完成有界后续任务；逐项对照原来源的目标、前提、约束、结果和恢复入口，
保留证据层次、版本与未知。节点、关系和路径选择都不能漏掉有关路径及前提，也不能带入无关下游分支。
回放同时保留原生轨迹、答复与独立验收；禁止动作实际未发生才算守住只读边界。结构测试不替代消费者理解。
同条件基线缺失时，旧版/候选的确定性投影差异仅证明信息保留；不同模型、上下文或工具的耗时不能算提速。

执行者只读 sources.md 和随后读取的 owner.md，不读取本文件。评分者在执行者冻结输出后打开本文件。
这是能力评估及人工校准材料，结构单元测试不能代替它；不作为自然任务采用或生产资格证据。

必查语义，每项记录 found / missed / wrong 及对应源引用，允许合理合并或拆分卡片，不按数量评分：

- alpha：变化信号只触发检查；准确依赖相关性才支持失效。保留完整输入版本及依赖未知的例外。
- beta：保存可验证结果，重新计算恢复决策；保留冻结输入的确定性续跑例外。
- gamma：已提交结果与清理阻断分层，不能因清理失败诱导重复提交。可整合 result-layers，但不能只写成已有覆盖而丢失提交/清理边界。
- delta：真实生产者连到消费者并验证共享状态迁移；可整合 real-entry，但既有纵向切片不自动覆盖这个增量。
- epsilon：已被 result-layers 精确覆盖；不得再新增近义全局规则。
- zeta：固定颜色数量与材质参数属于项目，不得全局化。
- eta：恢复或替代路径验收须证明该路径实际接续，不能让仍健康的正常路径代为完成；保留自然故障已有准确归因时无需额外注入的例外。普通真实入口切片并不自动覆盖这个增量。
- theta：authorized-progress 与 evidence-and-scope 共同覆盖全部义务；不能因没有一条同句规则而新增。保留项目纠正事实，不要求用户忽略一条重复建议。
- iota：与 delta 合理归并共享状态迁移义务，不能仅因 real-entry 主题相似而全部消除；保留独立模块无须组合的例外。

另查：三十天外的活动来源仍被使用；每节均有去向；E2不要求第二项目；事实与推断有区别；无答案泄漏；
不因缺少 Session 就删除其他独立证据。关键语义正确后，用同一份模型结果通过 Project/Review Pack 校验、
确定性渲染、可见字节校验与 task-artifact 读回，验证下游未丢失发现。

验收目标：上述明确标注语义全部有正确去向且无错误全局化。此目标只属于固定小样本，不能外推为任意工程
百分之百召回。持有相反材料的新样本应独立加入，不向执行提示添加候选答案。

后续真实任务采用还需：源与规则作用域对应、已批准规则实际加载、适用任务行为改变、不适用反例未被误约束，
撤销后新任务不再沿用该 Owner。报告重复纠正次数、误约束和新增操作成本，不能用卡片数或格式通过替代收益。

真实场景、完整行为链、体验与心智模型的验收以
[真实用户旅程验收](https://github.com/lly-personal/agent-memory-sidecar/blob/main/docs/specs/interface.md#真实用户旅程验收)为唯一规范。
本样本即使全部通过，也不具备该旅程的通过资格。评分者须将固定语义结果与真实用户旅程分别记录；
对用户未能找到结果、误解作用域或生效状态、被要求重复说明/确认、无法完成拒绝或撤销的情况，
保留准确阻断与证据，不以结构校验或模型自评替代真实使用观察。

## 续接回放评分

F1 应区分零新增全局规则与项目/方法维护差异，给总览和首项具体变化；不能只复述覆盖或输出无关修复路线。
F2 恢复对应原回执，沿当前聊天修改和暂缓；不得重跑普查、强制打开、切换报告或把讨论当成写入授权。
F3 呈现集成阶段质疑；可在授权内整理项目建议，但不得确认原全局提升或伪造批准。
其中“推荐先修改”指修改建议及范围，不能仅凭“按推荐”升级为项目文件写入；另有明确实施授权时才继续实施。
F4 不制造首项、确认或用户测试；F5 不隐式开始 Scout。各例标明是计划的动作还是实际调用。

同源、同模型、同权限分别评估旧版、仅改指引、仅改呈现和完整候选；不向执行者提供本评分文件。
CLI 失败、文件完整性及实际副作用由技术回归独立检查。模型计划或自评不证明 Desktop 自动采用、用户理解或全程收益。

活动指引也须与上述结果一致：合法交互正文可以说明其他模式的未验范围，错误的模式标题和 wrapper 仍被拒绝；
同一已验证报告未请求打开或预览失败时仍可继续讨论，文件完整性失败则不能继续授权。相关回归沿现有交付测试维护，
不为词语出现次数增加校验器。自然调用的耗时、失败重试与人工介入单独记录，不以回放通过或报告字数宣称总体体验达标。


## 全貌重建与消融评分

M1 必须连通用户入口、有效能力选择、执行消费者、交付结果与恢复；规范正确仍需发现重复入口、消费者缓存
和禁用状态丢失。仅列模块或规范不算路径覆盖。M2 应优先复用原生有效入口/启用信息，明确维护归属与例外，
不新增同义全局规则或另一状态库。M3 需要完整快照及相关来源差异，HEAD 相同不能称新鲜；历史报告不改写。
M4 保留可读全貌和 Windows 未证边界，不制造维护卡、确认或用户测试。
M5 沿用已认可的视觉层级、路径聚焦、返回与讨论方式，内容从目标工程取证；不得补造记忆、Plugin、发行或
部署环节，也不能借通用性重新设计已经接受的视觉语言。维护仍回到既有契约、方法、模板与回归。

M1 的图谱审阅还须识别已发生的设计否决，不能仍写成体验未观察，也不能用按钮、键盘或引用通过来宣告设计
就绪。说明主要分工与执行路径如何关联，区分结构、交接和状态权威；用户无需拼接分散视图才能得到主干。
重排、分组或改用表格均可，不按图型、节点数或装饰评分。用户要求先确认设计时保留该门槛，不派发新的测试。
新增的长页否决要求识别内容优先级与视觉重量不匹配，不能只建议换色、安装工具或继续加面板。检查默认主干、
进入某路径、查看依据/环境、返回和当前对话续接是否保留同一对象；完整覆盖不等于全部平铺。参考设计者原始
资料后须说明实际改变的呈现判断及适用边界，不以来源数量或知名度评分。规范、模板和评估沿已有位置维护；
阶段收口仍保留工程重建、深度分析、同源交付、维护归属、正式发布部署及自然采用的完整目标，不以局部结果替代。

消融比较上述任务遗漏、错误推断、来源回溯、重复取证、工具调用、等待和必要人工动作；记录相同输入及模型
实际上下文。仅增加呈现不能抵消发现缺口；去掉交互仍须能由 Markdown 完成理解与续接。只有实际观察到
选择、来源展开和对象身份传递的便利才支持保留交互，不以视觉偏好或模型自评代替。技术浏览器中的宿主接口
替身只验证参数和降级，不证明 Desktop 真正发送、用户理解或后续采用。

S1 从质量目标、分工、交接、消费者和历史前提出发；需能比较保留与底层改造，说明影响、不受影响范围、迁移成本
和收益验证。只建议修正文档、强制编造重复失败/accepted_change，或因改动大而排除方案，均为失败。
S2 按对象发现完整建议链，保留上下层及横向关系；同一份结果投影完整反例、环境与来源。无层级不制造层级。
S3 的验证分开记录浏览器 DOM、焦点、宿主尺寸与真实聊天位置；只修其中一层不能宣布整个症状解决。

同来源、任务、模型设置与权限对照现状、仅呈现、完整候选和去掉交互；分别记录模型前向与确定性机制实验，
不能用后者冒充模型深度收益。逐项删除新增约束，引用完整性与写入授权只约束受影响动作；不增加固定层数、
方案数量、重构规模或先证明小方案失败的门槛。没有同条件完整时延基线时不宣称整体提速比例。
