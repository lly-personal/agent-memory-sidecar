# 性能与共享资源

只读取与当前任务的真实触发、结果和约束相关的条目；下列方法不要求运行全部验证，也不授予外部写入权限。

## 性能结论须绑定用户任务与获批预算

适用：制定或评价用户可见长操作的性能与恢复体验时。

执行：围绕真实任务明确反馈、完成、取消恢复和资源释放的必要预算，并按具名阶段测量完整用户等待；数值门必须绑定代表规模、测量条件、批准来源及失效条件。无匹配批准门时只报告实测与归因缺口，不判性能通过或违约；观察预算仍只拥有其证据边界。

例外：简单无可感知等待的动作不增加仪式化预算表；契约已有完全匹配的性能门时直接依其裁决，观察到期本身不另设产品门。

## 共享资源受压先限流，再做有界恢复

适用：并发操作将共享有限资源作为真实瓶颈，或出现拥塞恢复时。

执行：按各类资源的具名预算限制在途操作，受压先减少新增负载，再按服务协议进行有界且避免同步碰撞的重试；恢复保留原有事务、幂等、取消和准确回收边界。重试耗尽报告准确阻断，不用增加并发掩盖失败。

例外：无共享竞争或操作不可安全重试时不添加并发与重试层；现有原生调度器已提供足够语义时直接消费，不再创建第二控制器。
