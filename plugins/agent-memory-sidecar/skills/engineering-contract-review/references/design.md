# 设计、状态与用户意图

只读取与当前任务的真实触发、结果和约束相关的条目；下列方法不要求运行全部验证，也不授予外部写入权限。

## 发布全量检查与日常消费检查分工

适用：将发布或维护检查用于高频消费入口，或引入跨环境缓存时。

执行：发布端证明承诺范围的完整性，允许身份匹配的证据复用；消费端验证当前依赖闭包，缓存只复用身份相同内容且不改变所选源 authority。声称原源可独立消费时，另须排除旁路缓存对结果的掩盖。

例外：消费者需要完整集合或依赖范围未知时保留相应完整验证；仅声明实际缓存命中路径时，无须额外证明原源当前可达。

## 界面简化要守住能力与用户习惯

适用：重构已有用户界面的信息架构或交互时。

执行：从真实任务核定现有能力、默认语义、必要决策、可发现性与恢复路径，明确保留、迁移或经确认退役；按获批意图验证受影响旅程，而非用现实现反向定义验收。

例外：已明确批准的语义变化不要求保持旧语义，但仍按新批准意图验证能力、迁移、恢复和真实旅程；纯装饰按实际影响缩小范围。

## 停止写入之后还要退出既有持久状态

适用：系统停止拥有曾经写入的持久偏好、配置或投影时。

执行：识别仍匹配旧系统完整归属指纹的持久状态，按授权范围迁移并读回；非匹配状态和用户后续选择保持不变，完成后不再重复接管。

例外：系统从未留下持久状态，或已读回确认相应状态不存在时，不额外创建迁移机制。

## 先允许表达意图，再在生效边界验证

适用：设计或审查用户声明、暂存与激活执行之间的边界时。

执行：区分意图录入、合法未绑定、交互草稿与生效资格；当前实现缺口不反向否定可记录的合法意图。正式生效前验证必需绑定和消费者闭包，不完备则零激活并路由准确Owner；未绑定对象保留为空，不用伪造连接补齐。用户新增或改名的合法输入沿用相同边界；可推导的展示信息由系统维护，不转嫁为新的业务输入。

例外：用户明确要求锁定编辑、强制权限或输入本身非法时可限制录入；系统未承诺可空、暂存或分阶段激活的对象不擅自增加这些状态。

## 完整集合按同一候选终态验证后原子激活

适用：在批量输入、生成或发布中声明完整集合，或准备激活原子配置代际时。

执行：按契约区分有序与无序集合，逐项核对声明与实际身份、基数及有语义的顺序；多出或缺少不能由计数或忽略规则掩盖，合并、过滤或展开须有具名语义。对契约要求的原子代际，完整候选终态核对消费者闭包，未闭合则零激活，激活后读回同代，否则按既定事务恢复。

例外：已批准独立激活或部分成功的契约按各自边界执行，不强制全工程事务；合法空集合不补造，无序集合仅枚举顺序变化不判drift。

## 证实上游错误后，向原Owner纠偏

适用：跨消费者核对已唯一证明某项上游维护事实错误时。

执行：向该事实的唯一Owner提出准确更正、受影响范围及读回标准，并按现有授权修正和验证下游；不把已证明的错误长期固化为各消费者私有补丁。需要兼容旧消费者时保留具名、可观测且可退役的变换。

例外：证据不能唯一定位上游错误时报告未知，不按编号、名称相似或位置猜改；已批准业务差异或明确过渡兼容不是错误。

## 适配按规范值比较，保留默认与表达式归属

适用：在配置、UI、冻结快照和运行适配器之间传递同一参数语义时。

执行：按字段的规范类型比较，区分外部声明、源拥有的默认或表达式、实例有效值和派生传输；从真实实例读回有效值，保留源表达式语义。仅有内部表示差异时在同一已授权操作中重投影或报告准确字段，不要求用户重做业务动作。

例外：用户改变真实业务输入、契约要求新一轮冻结或明确常量声明时，按该语义生成新操作或固化常量；无表达式和动态默认不增加额外快照层。

## 已有唯一上下文就继承，缺失才让用户选择

适用：用户入口需要确定上下文且已有上游声明或显式覆盖时。

执行：从当前authority继承唯一合法上下文，不再要求重复选择；确有消费者且上下文缺失时才请求必要输入。多个来源冲突时报告准确冲突，不从路径或显示名猜测；允许的显式覆盖保持可见、可清除并可恢复继承。

例外：用户明确选择独立上下文、产品任务本来需要比较多个上下文，或安全要求再次确认时，按该契约操作，不擅自压成单一上下文。

## 语义兼容、实际身份与传输字节分别判断

适用：用hash、版本或对象identity判断兼容、复用或传输完整性时。

执行：声明各身份拥有的事实，按具名兼容契约所需的业务语义、公共接口或ABI判定对应兼容层；物理字节证明准确对象完整性，实际执行版本进入运行证据。接口相同不替代行为、实际加载或部署一致性；合法表示变化不自动使未改变的语义失效。

例外：契约规定字节就是业务语义或要求精确字节同一时按其比较；接口相同但行为或ABI不兼容仍不能放行，语义等价未证不凭外观判断。

## 派生维护只由最小有效输入触发

适用：设计或修改由上游变化自动维护的派生投影时。

执行：识别真正决定该投影的最小authority输入，覆盖所有合法变更来源，只更新自身拥有的派生结果；按实际影响维护关联消费者，不让触发事件冒充无关成果失效。平台迫使扩大触发或写集合时明确影响、幂等与退役条件。

例外：平台只提供粗粒度事件时可先接收再按依赖过滤；契约明确要求完整投影归一化时按其集合执行，不因最小触发而漏合法成员。

## 状态、契约与成本的消融

适用：当前问题涉及重复状态、不必要的抽象或实际运行成本时。

执行：从真实消费者、读写归属和依赖判断状态能否推导，沿用已有跨模块契约，不把内部状态新造为公共协议。比较删除、复用、原生替代和移到显式维护的效果；保留当前验收需要的正确性、维护与恢复能力。必要物化须有失效、重建和退役边界，性能选择依实际成本，不固定优化顺序。

例外：隐藏或持久化本身不能证明实体必要；他人状态不能因缺少登记被删除。无相应状态或成本问题时不建立实体清单、不追加审查，内部分析也不转移原有归属。
