# ADR 0081：完整容量预演与正式 Owner 交付

- Status: accepted
- Date: 2026-10-16
- Decision owners: user, project_docs
- Scope: 容量预演、Owner 路由与交付协议；正式 Owner 内容变更、宿主安装和真实新任务采用分别需要对应授权。

## 已证问题与决策

一个已授权项目偏好先遇到 8 KiB 受管块饱和，合并后又遇到 1 KiB 单规则限制；第一次处理退回可选记忆笔记，
用户再次追问才完成正式部署。完整 `AGENTS.md` 当时可被宿主加载，不能把这两个 Sidecar 编辑预算归因于
Codex 项目指令加载额度。现有 bundle 预演没有普通单规则入口，并丢掉了单规则容量错误的详细信息。

采用现有规划器与 Skill 的最小修复，不增加规则库、Owner 写入服务或语义判定器：

1. `rule preview` 接受部署使用的七字段和 `--supersedes`；指定实际 `--target-file`，完全只读。
2. 单规则与 bundle 使用正式规划器，对完整拟议规则集同时计算单规则与整块容量。即使两种预算一起超限，
   也完整返回每条规则和整块测量；结构、作用域或 override 阻断时不伪造可部署结果。
3. preview 绑定 observed before、原始提案或 bundle、替换集合及成功时的 after hash。它只证明当前文件的
   规划结果，不代替批准、global parity、加锁后的 Fresh 重算、真实写入或后续采用。
4. 普通单规则、CLI、不可变 runtime 与 Scout 消费者使用一致契约；bundle v2 保留 v1 字段并增加容量明细。
   新 Scout 同时读取旧 v1 和新 v2；新 Core 的 v2 必须与支持它的 Scout 一起交付。
5. Owner 归属先于容量判断。方法和规范正文通过已授权普通项目工作落入正式 Owner；必需行为保留在
   `AGENTS.md` 的准确触发与读取入口。逐项核对旧义务、适用条件和例外，不用缩短后的语句冒充语义等价。
6. `route_to_owner` 只表示归属判断，不表示部署。Skill 分别报告路由未实施、正文落地、入口部署与采用证据。
   容量失败保持未部署，禁止把可选 Memories、笔记或摘要作为正式规则部署的替代。

## 预算重新评估

保留 1,024／8,192 字节作为本轮兼容的编辑预算，不把它们声称为模型能力上限或经测定的最优值。
单条以 UTF-8、规范化 LF 渲染计数；整块以目标实际 LF／CRLF 渲染计数，包含标题、标记和换行。
完整文档正文不占 Sidecar 受管块预算。中文和 emoji 必须按实际 UTF-8 计数，不用字符数近似。

本次事实证明了预演和交付缺口，也证明受管块归并可以释放空间；未证明去重后必要独立规则仍普遍超过预算，
更未证明扩大预算后的后续采用可靠性。因此不盲目扩容，也不为凑预算拆分规则、删除例外或绕到块外追加。
后续复审记录去重后必要规则、语言与格式开销、准确失败层、Owner 路由完整性及用户请求的新任务采用结果。
若必要规则仍被预算阻断，应重新决策数值或作用域，不再让用户重复压缩或督导；不把当前数值当作不可变公理。

## 验收与交付边界

- 单规则和整块同时超限时，一次预演保留两种准确测量与全部候选；失败不返回 after hash。
- 精确边界可通过，多一字节被拒；中文、emoji、LF／CRLF 与大块外正文均有覆盖。
- CLI 和不可变 runtime 从同一输入返回相同预演；不创建 Store、proposal、锁、journal、目录或目标文件。
- preview 与正式隔离部署的 after hash、规则顺序和内容相同；归并保留未选择规则与块外字节。
- Scout 不允许容量超限的 v2 receipt 被标为 ready，同时继续读取合法 v1 receipt。
- Scout 的用户提示按准确测量分别解释单条、整块和同时超限；旧 v1 缺少明细时只报告已知事实，不混用两类预算。
- 隔离正式 Owner 正文及路由规则逐字读回；该证据只证明内容与入口交付，模型理解和后续采用另行验收。
- 失败不消费授权；现有 scope、before 漂移、override、原子写入和撤销回归继续通过。
- 全局先验证双目标 parity，再预演宿主实际目标，使 override 判断与正式部署一致；源仓库旁的 override 不误阻断宿主部署。

最短排查顺序：读取实际 target → 同时预演单规则和整块 → 核对 Owner 义务去向 → 在已有授权内部署 →
读回正文与入口 → 分开声明后续采用。需要观察宿主加载时优先使用宿主原生指令预览；无需为读取输入另建模型任务。

语义完整性由 Agent 根据准确 before/after 和义务矩阵负责，确定性层只证明字节、结构与事务事实。
工程隔离验证本身不授权正式个人 Owner 修改或本机运行时升级；已获授权的安装应保留 Owner 并单独验收，
不得把隔离验证或安装完成冒充真实 Desktop 新任务通过。
