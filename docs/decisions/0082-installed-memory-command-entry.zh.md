# ADR 0082：普通任务使用随 Skill 安装的 Core 入口

- 状态：Accepted
- 日期：2026-11-02
- 范围：Core 安装投影、Doctor、Bootstrap 回执与实际入口回归；不改变授权、Owner 或 Store 契约。

## 需求与反证

用户应在明确协作偏好后完成一次授权，并在普通项目继续查看、修订或撤销规则，无需定位 Python 包或重复安装。
实际故障表现为安装与 Doctor 成功，但 Skill 调用全局命令时找不到 `agent-memory`。隔离复现证明，setup 与
Doctor 依赖的临时 `PYTHONPATH` 掩盖了普通消费者缺失的可执行入口。PR #45 的中文回执又在非 UTF-8 管道下
触发 `UnicodeEncodeError`。两者都必须通过实际进程验证，不能以文件存在或内部函数返回替代。

## 原生能力核验与选择

核验日期为 2026-11-02；本机 Codex CLI 为 0.166.0。官方 [Skill 机制](https://learn.chatgpt.com/docs/customization/overview)
直接支持随 Skill 携带并按需运行 `scripts/`。因此采用这一现有入口，将现有 Core 源码作为安装投影随 Skill
原子安装；源码仍只有 `src/agent_memory_sidecar`，没有手工维护副本、服务或新的运行数据库。

对照过的其他原生入口：

- [Plugin onboarding](https://developers.openai.com/plugins/build/plugins) 可调用包内 setup Skill，能改善初次发现；
  但它不自动提供 Core 命令，也不能证明当前宿主上的后续调用。本次不增加第二个 setup 入口。
- 同一官方文档提供 Plugin hooks、`PLUGIN_ROOT` 与 `PLUGIN_DATA`。这些变量属于 Hook 执行上下文，不能假定
  普通工具命令也具有它们；安装或启用 Plugin 也不等于已信任 Hook。迁移现有事件入口不是本次故障的必要修复。
- [原生 MCP](https://developers.openai.com/plugins/concepts/skills) 可提供结构化工具，但本次工作只需本地 Core；
  引入服务器、连接配置和另一套工具入口不能消除现有授权与发布责任，增加的实体没有当前验收需求。
- wheel 的 console script 继续支持 CLI-only 安装；将它设为 Desktop 的隐式前置条件会重新引入包环境和 PATH 依赖。

## 决定与验收

1. 生成的 Skill 指向自身 `scripts/agent-memory.py`，保留实际项目 cwd、活动 CODEX_HOME 和原有操作参数。
   使用宿主已存在的 Python 3.11+；不修改 PATH，不安装第三方依赖，不要求用户搬运内部路径。
2. Skill 内容身份覆盖入口和 Core 文件，沿现有原子安装及回滚交付。Doctor 在项目目录移除源码环境变量后
   执行这个入口；空输出或失败都不能成为就绪证据。
   日常入口只开放 rule、proposal 和 doctor；安装、迁移和指令分发继续从已验证 Bootstrap 执行，避免将安装
   副本误当发行源码而覆盖来源身份。既有目录替换存在短暂切换窗口，不承诺并发升级期间无中断调用。
3. 普通入口回归在隔离 Owner/Store 中执行查询、未授权拒绝、显式部署、修订、撤销及提案确认，退出码、JSON
   与 Owner 读回共同判定。模拟项目路径含空格，不依赖全局 console script。
4. Bootstrap 输入输出明确使用 UTF-8；回归强制非 UTF-8 默认管道，检查中文回执与直接 renderer 完全一致。
5. 回执分别报告安装、入口条件与 Scout 实际运行。源修复、CI、发行、主机部署、后续自然采用各有独立证据。

这些测试证明运行入口与确定性操作，不证明模型在所有自然场景都会选对 Skill，也不证明长期采用、第二台设备
或 Scout 全流程。出现新的宿主原生能力或实际消费反证时，重新比较必要实现，不以本 ADR 固定实现手段。

## 部署时发现的自检误判

v0.5.1 已发布后的主机部署暴露了此前空 Store 测试没有覆盖的状态：Hook 捕获测试事件时会执行正常的过期
清理，而自检以共享 Store 的总事件数必须增加一作为成功标准。并发任务同样会改变这个总数。失败分支还遗留
自己的临时事件。因此，即使事件已正确捕获，也可能拒绝激活。

v0.5.2 只核验本次随机 session 对应的 event 及当前 session 引用，并在成功或异常出口清理该 session 的探针。
`event_delta=1` 表示该独立探针的新增，不代表共享 Store 的全局计数差。既有过期清理、授权和事务协议不变，
不增加全局锁、运行数据库或第二个自检控制器。回归包含真实 zipapp 上的过期事件、捕获期间的无关事件、空输出
及捕获后异常，既证明错误前失败/修复后通过，也证明无关事件仍保留。

本机部署失败会撤回该次部署完成声明，不撤回已验证的发行与日常入口代码证据。不可变发行不能覆写，修复必须
通过后续版本发布后重新取得部署计划，并分别回读实际安装、普通任务入口和后续采用。

## 普通 Desktop 入口的行为反证与回归

2026-11-02 的受控验收使用独立项目和 GPT-6.1 Terra / high。首次普通库存任务未误触发记忆；带有反复使用
线索的纠正只改变了当次报告。更明确的后续协作要求触发 Skill 后，执行者先猜用了 Python 3.9，恢复正确解释器
并查到空规则集，却直接写入项目指令和可选记忆笔记，没有执行 Core 部署；终态又声称长期状态未变更。
恢复测试文件后，同一聊天还凭旧上下文误报已有覆盖。这些行为说明命令可用不能代表消费流程正确。

修正仅落在现有生成 Skill：先查询解释器并检查版本，分类（包括已有覆盖）前读当前规则和所据 Owner，
缺少当前宿主事件或命令失败时不得改用直接编辑或可选笔记保存规则；若已经写入，必须如实报告具体变更。
不增加另一套写入器、审批服务或运行数据库。既有指令文本测试只证明分发内容，不能冒充模型行为回归。

沿用本工程的真实旅程验收位置，维护以下已执行场景和未证范围；任务级原始回执留在受限验收资产，不进入公开源码：

| 场景 | 本次结果与后续回归判据 |
| --- | --- |
| 无候选的普通报告 | 原版与候选版均安静完成；不因项目身份强制治理 |
| 已有上下文中的 Owner 已改变 | 原版误报已有覆盖；必须读当前文件，不能凭旧对话作完成声明 |
| 解释器与失败出口 | 同一强纠正输入下，候选版正确发现解释器，并在事件不可用时保持 Owner 和笔记不变；单次受控对照不证明普遍可靠 |
| 明确记住与一次授权 | 用户实际输入后，候选版完成 list、preview、deploy、readback；一次授权消费，没有再次索取确认 |
| 后续采用及例外 | 新的同模型聊天只收到普通库存任务，采用已部署标题；随后原文输出不添加标题 |
| 被动建议及确认 | 首次线索未出现建议，完整确认分支尚未验证；不能以明确记住成功代替 |
| 撤销入口 | 工具代发请求没有可匹配的用户事件，候选版保持规则不变并报告失败；工程清理和 Core 隔离撤销回归不能算作该真实入口通过 |

工具创建或代发的聊天消息与用户从 Desktop 输入框提交的消息，本次并未取得等价的事件证据。后者已观察到
匹配的当前事件；前者附近的后台事件不得借用或重建为用户授权。后续验收先绑定实际入口和上下文，再判定权限
及用户体验；用户停止参与测试时，继续独立可执行工作并保留缺口，不反复索取测试配合。

完整交付效率尚无匹配的前后基线。先前约 75 分钟的整轮交付包含新增研究、修复、两次发行、部署、审查及收尾，
不能与单个验签阶段的 48.63 秒到 5.37 秒比较。本次准备项目、真实输入和失败纠正的成本均进入任务证据，
不剔除人工等待，也不把工具代发所省的操作计作真实确认成功。现有规范足以承载这些边界，不新增顶层治理副本。

## 入口选择的重复条件与剩余验收边界

后续源追踪发现 Ambient 的允许触发清单没有列出当前建议回复和撤销；生成 Skill 的 description 与正文也各自维护
不同的清单。底层公开接口支持这些操作，外层选择条件却可能先将它们排除。这是可直接确认的契约遗漏，但尚不能
证明它导致了先前的模型漏触发：那次工具代发没有取得对应用户事件，首次真实输入又受到已证实的旧覆盖判断影响。

因此由已有 Skill description 单独拥有运行时选择条件，Ambient 和正文引用它；description 明确包含已有规则操作、
建议回复与无须先说“记住”的未来偏好。正文区分未来偏好建议、当次输出指令和已有规则操作。被动候选仍先预演并
生成一张建议，明确回复消费原建议；清楚的撤销请求只执行一次并读回，不再要求第二次确认。不增加语义 Hook、
关键词分类器、审批服务或另一份状态。

必要回归沿用 `test_cli_and_package.py`：安装后的实际 Hook 子进程接收隔离的用户事件夹具，生成当前事件；随后从
普通项目运行已安装入口，验证 pending 不写 Owner、一次确认只消费一次、重复确认被拒绝，以及独立撤销和读回。
这比直接调用 Ledger 填入事件更完整，但仍是隔离机制验证，不能称为用户输入框验收。

同一批隔离 Terra/high 观察中，旧版和候选版都完成了建议创建、一次确认和撤销。因此没有得到模型行为的红绿差异，
不能把清单纠偏升级为“被动发现已修复”。这些观察明确提供了 Skill，也没有检验自然发现；低层回归和版本分发测试
不代替这一缺口。先前工具创建或代发路径的缺失事件也不能靠补录、借用或重建生产授权解决。

当前宿主工具没有提供输入框自动化，Computer Use 已明确拒绝控制 Codex。用户已要求不再配合验收，故不能再次
要求人工发送测试消息，也不能改用其他 UI 技术绕过同一限制。完整 Desktop 被动建议、确认和撤销仍未验收；只有
可用的受支持真实入口或后续自然使用产生同身份结果时，才能更新该层结论。已获授权的实现、回归和发行继续交付。
全流程等待与人工介入仍按实际运行记录；没有匹配基线时不从局部耗时或省去测试步骤推导整体收益。

### 隔离会话复验

同日随后由宿主创建新的 Windows worktree 会话，使用 v0.5.4 的不可变发行解析结果和原生 Desktop 项目清单复验。
dry-run 为 `noop`，`verify-consumer` 返回 `ready`：6 个可见项目均已检查，发现的两个项目级同名 Skill 均为
`exact`，消费者入口为 `verified`。这项新证据替代前述待复验结论，只证明安装及消费者范围，不证明 Scout 已运行。

独立 Scout 会话已通过 `linked_worktree` 检查，却最初错误地报告缺少输出根目录。对实际宿主上下文的复核发现，
本任务已有项目之外的独立输出目录和文件预览工具；执行者遗漏了该目录授权。重新依据自身上下文执行
`inspect-output` 后通过，未修改源码、安装、Owner 或保护规则。该错误是本次执行判断失误，不是宿主未提供能力；
纠正后的运行不能作为无提示自然发现已经可靠的证明。

### 设计要求、真实触发与未完成项

验收继续以 [L1 产品定义](../specs/axioms.md#产品定义) 和
[项目任务前门](0079-project-session-front-door-and-scout-terminal-contract.zh.md) 为准：稳定核心将用户一次明确授权的
必要规则增量写入正确作用域的 `AGENTS.md`，后续任务采用，且可以查看、编辑和撤销；Hook、Store、安装回执和
Git 提交都不能替代这些结果。Scout 另属只读复盘入口，用户在当前项目触发一次后，由宿主处理隔离，交付有具体
项目语境的完整中文建议；查看建议不授权写入。用户不应被要求理解内部目录、准备 worktree 或重复解释项目。

本轮回读原始任务、工具调用和实际宿主上下文后，按首个失效消费者重新判定：

| 环节 | 实际证据、根因与处理 |
| --- | --- |

## Windows 部署后原聊天验收的断点（2026-11-02）

后续 Windows 原生任务记录确认 v0.5.5 已安装，用户刷新后在原聊天要求消费者与项目能力验收；Agent 只执行了
Release 解析和 `noop` 检查，随后依据 Bootstrap 的“已加载新任务”前置条件，要求用户另开聊天。安装证据仍有效，
但该次请求未完成项目范围检查。v0.5.5 去掉了 Scout 的新任务门槛，却没有同步消除 Bootstrap 的同类限制。

根因是把会话加载证明误设为独立只读检查的前提；实际 `verify_workstation_consumer` 只观察安装身份与项目 Skill，
不读取会话加载事实。旧实现还会在 `consumer_verified=True` 后移除加载未证提示，使技术就绪容易被误读为采用通过。
[当前原生 Skill 文档](https://developers.openai.com/codex/skills/)说明变更支持自动发现，未显示时才重启；这不证明
任一具体 Windows 会话已经加载，但也不能支持强制刷新再新建聊天的通用门槛。

修订继续使用既有 `verify_consumer`：用户已要求验收时，同任务读取已验证 portable 内容并检查目标主机项目范围；
只要求安装时结束，不额外枚举。Pack v3 保持兼容，`ready/verified` 仅表示安装与范围检查，始终保留加载、采用、体验
和其他主机未证。没有增加任务、队列、审批或验收机制，也不改变身份、漂移、Owner 与只读约束。

最小消融对照使用相同 Windows 场景和输入：独立 baseline 路由观察停止并要求新任务，candidate 继续同聊天只读检查；
这只是指令路由观察，不能替代 Windows 执行。正式回归通过真实 CLI 分派、项目目录读取与 renderer，替换边界仅为
外部主机观测；旧版缺少未证声明而失败，修订后保留声明且不改项目文件，非 exact 主机仍拒绝。现有漂移、清单不全
与不安全路径回归继续适用。

该结论适用于用户已授权验收且目标主机可达、Release 身份与项目清单可核实的场景；宿主发现机制变化需增量复核。
当前维护任务只能读到 Windows 历史与 Mac 项目清单，不能用 Mac 检查补证 Windows。新版远端部署、真实加载与自然
体验在取得对应主机新证据前保持未验，不再要求用户执行验收测试。
