# Scout user journey repair

## Intent and delivery target

The user needs to understand what a project achieves, how its capabilities cooperate, why its current boundaries exist,
and what is actually known about delivery. Reading should move from a useful explanation to a chosen detail without losing
the overall context. Continuing a discussion must preserve the exact report, object and visible journey. A large diagram,
more pages, more rules or passing validators do not establish that outcome.

This repair changes the existing Scout workflow, renderer and continuation dispatcher. It does not change Core governance,
the reviewed project's Owners, installed Global Owner instructions or frozen prior reports. It spans the existing Skill,
its presentation/CLI contracts, affected regression assets and user guide. No new service, graph database or model authority
is needed. Source delivery, installed adoption and human comprehension remain separate results.

## Evidence and revoked claim

The failed user run used the same Scout bytes as the public source. Its report contained 28 nodes, 51 edges and six journeys,
yet the overview's relationship region was empty: the renderer required both endpoints to be immediate root children.
The substantive handoffs lived below those groups. The visible default journey was also chosen during rendering without
being committed to continuation state, and the synthetic overview ID was sent as if it were a real node.

The review brief led with recommendation counts rather than the engineering explanation. Retrieved history page counts did
not demonstrate that their substantive contents had been compared. Recommendations offered process completion without
enough source-backed architectural tradeoffs. The user's rejection invalidates this run's analysis/presentation experience;
artifact integrity and unrelated Core mechanism evidence remain valid. Previous synthetic browser and unit successes did
not cover these real shapes. Private reports, task IDs and transcripts are retained locally, not published here.

## Research and resulting choices

- [C4 diagrams](https://c4model.com/diagrams) support levels chosen for explanatory value. Adopt gradual detail, not a fixed
  number of layers. [Dynamic diagrams](https://c4model.com/diagrams/dynamic) explain a specific scenario; do not concatenate
  unrelated journeys into a fake universal sequence.
- [Structurizr navigation](https://docs.structurizr.com/ui/diagrams/navigation) connects views of the same model. Adopt stable
  identity and return paths. Do not create a second graph model or copy a full architecture editing application.
- [Cytoscape compound nodes](https://js.cytoscape.org/#notation/compound-nodes) can support large interactive networks, but
  full graph navigation is not required to explain this bounded reader journey. Start with native disclosure and a measured
  diagram of the visible groups; add a library only if a faithful consumer test exposes a concrete unmet layout need.
- The locally installed native `visualize` contract supports inline fragments, optional state and `sendFollowUpMessage`.
  Use it as the presentation transport when exploration helps. Preserve a readable same-source Markdown fallback.
  Widget state is best-effort context, never authority or proof that a message was sent. No new host API is presumed.

The user later identified a real native visualization as a positive example and explicitly clarified that the approval
concerned its visual language and interactions in that scenario, not its role/scenario content structure. The candidate must
learn its restrained hierarchy, native controls, theme integration and local feedback without turning those particular
content groupings into a universal template. The example's later unresolved questions about field effects remain a separate
content gap. This correction supersedes the initial interpretation that the example approved a particular reading structure.

## Repair sequence and acceptance

1. Source comprehension: expose relevant passages to the reasoning pass, connect intent, consumer, observed result and
   counterevidence, and compare legitimate retain/change choices. Independently reconstruct the frozen failed case before
   reading its recommendations. Evidence retrieval is not semantic coverage. No word-count or card-count quality gate.
2. First read: both inspect and review briefs explain goal, boundary and a real entry-to-result journey before advice.
   The initial view explains responsibilities in ordinary language, without raw schema kinds or all descendants.
3. Optional map: retain the overall location while exploring collapsed groups. Aggregate descendant relationships with
   access to their exact original edges; retain internal links and unknowns. Filter relationship meanings instead of
   showing every edge at once. No relationship may disappear solely because it is below the initial groups.
4. Continuation: the visible journey, selected node/edge/advice and project overview resolve against the verified original
   artifact. Missing objects reject; stale source remains historical. Back, reload, bridge failure and no-bridge fallback
   retain useful context. A click never approves implementation or a rule change.
5. Real regression: replay the frozen failed report through the candidate renderer without rewriting it; separately compare
   a source-first reconstruction with the independent reading. Exercise overview, task path, detail, return and continuation
   in a browser, including narrow width and keyboard. Distinguish browser stub evidence from native user transmission.
6. Delivery: run the full required suite, link and whitespace checks, relevant Skill validation and scoped cleanup. Record
   technical results, source/deployment state, and remaining human/host checks explicitly. Do not mark user experience passed
   solely because tests or screenshots succeed.

## Results

The existing pipeline now renders an engineering explanation before recommendations, preserves causal claims in normal
journey reading, exposes descendant relationships through collapsed groups, and resolves exact selected objects and journeys
from a verified report. Multiple visible parents retain the shared object's identity instead of selecting an arbitrary parent.
Advice linked only through a journey recovers the same related objects as the UI. Host theme tokens and restrained type
hierarchy replace the previous separate outer panel; advanced views remain optional. No dependency or persistent store was added.

- Red: the new brief and selection regressions failed on the prior code. In a real browser the frozen failed report showed
  zero root relationship controls and failed the descendant-relation assertion.
- Green: the same immutable report through the candidate exposes all 28 non-containment edges. The original 51-edge map,
  advice and evidence are unchanged. Nine candidate cases pass browser navigation, selection, continuation fallback and state
  checks, including shared-parent input in both orders. Twenty-eight width/theme/view combinations fit 360/736-pixel widths.
  Keyboard activation and captured rendered views were checked. Follow-up transmission used a stub, not a real user message.
- Native CLI recovery consumed the original actual final reply and returned the selected object and journey. It reported
  `source_status=changed` against the now-changing target checkout, while original artifact integrity remained verified.
- Independent source-first review found and reproduced three candidate defects: lost consequence claims, journey-only advice
  recovery and ambiguous shared-parent projection. All three were corrected and rechecked.
- The old report's 20 journey edges repeated their labels in claims. Re-rendering that material cannot demonstrate deeper
  analysis. A separate, traceable source-first analysis was therefore produced from the same frozen source; old artifacts
  remain unchanged. It explains real state changes, legitimate design tradeoffs and remaining unknowns. This is a bounded
  engineering reassessment, not a controlled model-quality experiment or a new natural Scout run.
- The new interpretation also went through the existing validator, renderer, immutable delivery and exact selection recovery.
  All seven reconstructed journeys retained their entry and handoff consequences in four width/theme combinations. Parent
  review corrected an over-narrow Deadline-only summary before final delivery; superseded candidates were retained rather
  than overwritten. The latest browser capture was unavailable because the window was minimized; DOM checks still completed.
  Earlier candidate screenshots and keyboard checks are retained with their own scope, not relabelled as a final native capture.
- The repository suite ran 324 tests. In the ordinary working tree one discovery-path check failed on pre-existing ignored
  bytecode-only directories; those unowned historical files were retained. The same candidate in an owned isolated worktree
  passed the full suite with five environment-dependent skips. Affected map tests, active document links, Skill metadata and
  whitespace checks also passed. Subsequent presentation-only adjustments receive focused browser regression.

This is local source delivery. Public release, installed Skill adoption, native parent conversation scrolling, real follow-up
transmission, the user's acceptance of this candidate and sustained cross-project improvement are not established here.
The original failed user experience remains failed; its technical repair evidence does not retrospectively change that result.

The owned validation worktree was archived with byte-for-byte verification and removed; Git registration and physical absence
were read back. Original working changes, private failure/replay evidence, other worktrees and historical bytecode were preserved.
No commit, push, release publication or installed-source modification is part of this local candidate delivery.

it linked the receipt but omitted the required in-message binding. Delivery instructions now require the complete generated
receipt in the composed final and native-history readback on continuation. The rejected real shape is retained as a regression;
the parser was not relaxed.

interaction pattern or content grouping is universal. The existing overview remains reusable; Delivery can freeze another native
fragment through `--visual-input`, and `--text-only` can omit inline interaction while preserving evidence and recovery. These
paths keep existing schemas and authorization. Exact bytes establish integrity, not semantic fidelity or user comprehension.

alternative representations still require behavioral assessment.

with the source node. Navigation now preserves the entered ancestry; ambiguous ancestry stays at project/object scope. Evidence
retains both endpoints and exact relationship identity. An unrelated selection clears the previous journey, and recovery rejects
contradictory object/journey pairs while preserving legacy graphs without typed edges.

The isolated suite ran 325 tests successfully with five environment-dependent skips before the final navigation corrections;
affected unit and browser regressions cover those corrections separately. Native-style browser checks retain the original red
