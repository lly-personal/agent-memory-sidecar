# Scout system reconstruction acceptance

- Date: 2026-11-04
- Baseline: public `67bb9f1` / `v0.5.12`
- Candidate: Project v7, Review Pack v8, Delivery v2; the commit containing this record
- Scope: generic engineering reconstruction, layered advice, fixed presentation and receipt recovery

## Findings that changed the implementation

The prior card contract required rule-shaped evidence and accepted-change history. It could not retain a source-backed
engineering hypothesis without inventing those fields. Engineering cards now carry alternatives, costs, validation conditions
and optional parent advice. Rule candidates retain their existing eligibility and authorization requirements.

The prior representation could list modules and paths but could not distinguish structural ownership, constraints and evolution.
The new typed relationships reuse the same objects, sources and coverage. Unknown hierarchy does not block unrelated reading;
only structural containment cycles and damaged references invalidate the affected result.

An independent source-first review of two existing projects changed the candidate advice. An existing common reader was not a
reason to merge stores with different write semantics. An offline checker was not evidence that a real account write failed.
History titles were also insufficient grounds for excluding mixed engineering conversations. These corrections are retained in
the existing discovery examples; private transcripts and project identities are not published.

## Mechanism and presentation evidence

- Full local suite: 322 tests, six environment-dependent skips; affected project-map suite: 16 tests.
- Legacy reports remain readable. A mixed pack keeps engineering discussion out of rule selection and Core preview.
- In a Chromium wrapper, the same restored snapshot previously caused 18 DOM mutations; the candidate caused zero and kept
  focus. Programmatic navigation uses `preventScroll`. Repeated selection does not save or redraw identical state.
- A legal quoted advice identifier exposed an unescaped teaser attribute. The fixture now contains that identifier and the
  browser check verifies exact selection and recovery without narrowing the identifier contract.
- Browser checks cover hierarchy, back navigation, relationships, source-bound discussion, bridge failure and state recovery.
  Six views fit at 320 and 736 pixel wrapper widths in light and dark appearances; keyboard activation was exercised.
- These browser checks use an owned local wrapper and a stubbed follow-up bridge. They do not prove the Desktop parent
  conversation's scroll behavior, real follow-up transmission, human comprehension or sustained adoption.

## Ablation and limits

With identical synthetic sources and engineering hypotheses, the prior contract and presentation-only arm reject the engineering
card shape. The full candidate retains it without rule actions. Removing interaction retains the evidence and alternatives in
Markdown, but does not measure the cost of locating and returning to an object. Removing an unavailable journey does not block
the remaining map. A separately altered report copy fails integrity recovery.

This is a deterministic mechanism comparison. It is not a controlled model-quality experiment: runtime model metadata and a
matched full user-session baseline were unavailable. Source-first independent assessment, technical regression and human
understanding remain separate evidence layers. No percentage improvement or complete experience qualification is claimed.

The inspected Desktop visualization channel accepts follow-up `prompt` and `title`, but does not forward the Apps SDK
`scrollToBottom` option. Adding that unsupported parameter would not establish a fix. Host height observation and conversation
scroll control remain outside the local DOM result. Native parent-scroll behavior stays unverified; no parent-frame manipulation,
fixed-height scrolling container or additional service was added.

Publication, installed versions, effective entrypoints and real adoption must be read from their own receipts. This source record
does not assert that a release or deployment has already happened.
